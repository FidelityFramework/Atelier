# 05 - Missions

The long-horizon benchmarks of 2026 measure a collapse. Frontier agents that resolve two-thirds of single-issue tasks on SWE-bench Verified drop to roughly a fifth on [SWE-EVO](https://arxiv.org/abs/2512.18470)'s multi-release evolution tasks, and in every benchmark of the family the repository is opaque text and progress is measured by test passes. The deficit is public and quantified. What no system in that literature gives the agent is a semantic model of the project's state over time paired with a checkable objective. Atelier's mission machinery is designed to supply exactly that pair.

## A Mission Is a Predicate Plus a Trajectory

A mission is a target condition expressed over the specific graph, with progress read off the temporal ledger as the predicate approaches satisfaction. Examples that fall directly out of the graph's existing annotations:

- every subgraph marked for the inference pipeline is reachable on the NPU target (a bitvector predicate, over the per-target reachability CCS is scheduled to carry; [02](02_specific_graph.md))
- the obligation set for the crypto module is fully discharged at Tier 2, with the two Tier 4 properties type-checked against the Rocq-proved rule library (an obligation-class predicate over [our four-tier verification architecture](https://clef-lang.com/docs/design/categorical-foundations/formal-verification-compilation-byproduct/#the-four-tiers); CCS mints and discharges the Increment 1 families today, and the families this predicate names are scheduled)
- BAREWire contract v3 is adopted on both sides of every crossing and v2 is retired (a contract predicate, read from the resolved contract version on each PSG crossing edge, with the `ContractRevised` history of [document 04](04_temporal_ledger.md) as its burn-down)

Our published design left a slot for this concept: `CompilationGoal` appears in [the temporal-PHG material](https://clef-lang.com/docs/internals/pipeline/hyping-hypergraphs/) as the key of a traversal-history map, named once and never defined. The mission predicate supplies that definition.

Progress is measured against the ledger: predicate satisfaction over the snapshot sequence is a burn-down computed from ground truth rather than from an issue tracker's self-report. A predicate that held and now fails is a structural regression, caught by graph comparison before any test observes it. The nearest mature practice is proof engineering: the Lean community's [blueprint](https://github.com/pitmonticone/LeanProject) infrastructure renders a formalization as a dependency graph of statements colored by status, and the [Equational Theories Project](https://arxiv.org/abs/2512.07087) tagged theorems as machine-readable goals and dashboarded twenty-two million implications to zero. Our four-tier obligations make that practice native here, since obligation burn-down is proof-frontier tracking on the same graph CCS already maintains.

Missions also have an honest boundary, drawn by [the PHG paper's](https://arxiv.org/abs/2603.17627) own Rice-theorem discussion. A latency budget is a measured property of a running system. The graph holds the structure bearing on it, never the number, so a mission decomposes into graph-checkable subgoals and extra-graph criteria, and the tooling is designed to label which is which rather than blur them.

## The Capability-Arrival Advisor

The advisor is the mission machinery's flagship application, and its scenario is concrete. A project matures on the CPU. An FPGA enters the picture as a sidecar accelerator, with an eBPF program steering the network path. The moment the target set changes, the advisor's question is: which subgraphs were shaped by target scarcity rather than by structure, and what would move.

Each stage reads from machinery already described, and every fact in it is the compiler's. The advisor reads; it computes no placement and invents no score.

1. **The fence-sitting record.** Backend selection is coeffect-driven, and a subgraph that could have lowered either as control flow or as dataflow would be a representable condition if CCS carried the admissible-lowering set as a saturation annotation: the enumerated lowerings and the coeffects that decided, no number. No such annotation exists today, and whether CCS should own it is an open contract question ([document 04](04_temporal_ledger.md)). If it lands, the ledger's `Reclassified` deltas over it preserve the close calls with their deciding factors, and a slice of today's graph that shows CPU-shaped code gains a history that says which of it was structural. This stage is sequenced after that decision, and the advisor stands without it.
2. **The latent tier.** Adding a target would widen every reachability bitvector by a bit, and the latent nodes preserved with their saturated annotations would reactivate at boundary cost. The DTS+DMM design carries the not-taken paths precisely so that a configuration change re-poses the question; the bitvector and the Live/Latent/Fresh model are Phase 1 of `clef/docs/fidelity/phg/PSG_to_PHG_Plan.md`.
3. **The placement diff.** CCS re-saturates the solution under the widened `PlatformDescription` set, and the advisor reads the placement annotations that result and the ledger's `TargetBitChanged` and `Reclassified` deltas between the two elaborations: which nodes' best-fit target changed, evidenced by the declared transfer costs, word widths, and locality the compiler resolved. What-if saturation under a hypothetical target set is a CCS-owned contract item with no API today.
4. **The contract from the cut.** Each proposed migration induces a partition, the cut set is exactly enumerable, and every crossing edge would carry its type and layout (layout as a joint constraint has landed in CCS for string literals only), so the proposal arrives with the new BAREWire contract skeleton attached.
5. **The steerable surface.** The advisor presents the proposal as a choice, in the pit-of-success posture [the Atelier entry](https://clef-lang.com/docs/tooling/atelier-the-fidelity-workshop/) commits to for arena hoisting: the compiler does the safe thing, the developer sees the faster thing and chooses. Accepting opens a migration mission with the burn-down riding the ledger.

Reliability in this design attaches to four properties, all of them the compiler's: the enumeration is complete because reachability is exact, the boundary is exact because the cut is computed, the contract is type-correct by construction, and the re-evaluation is deterministic because CCS performs it. The performance payoff stays an estimate until measured, on the far side of the Rice boundary, and the advisor is designed to present it as such. A tool that says these six subgraphs are structurally eligible, here are the boundaries and contracts, here are the fit estimates, you decide, is the version of this capability that survives scrutiny.

The demonstrated seed is [HelloArty](https://github.com/FidelityFramework/HelloArty), which infers bit widths and machine classification from source, and [HelloNappy](https://github.com/FidelityFramework/HelloNappy), which derives tile count from a kernel's shape. The advisor is that same inference discipline run comparatively, across targets and across time, with the inference in CCS each time.

## Deterministic First, Learned Later

The temporal graph learning literature argues, at present, for restraint about the learned tier, and the argument comes from that field's own benchmarks. Non-trainable baselines beat temporal GNNs on node affinity prediction in [TGB](https://arxiv.org/abs/2307.01026), a zero-parameter recency heuristic [outperforms neural methods](https://arxiv.org/abs/2309.15730) on medium and large datasets, and the [T-GRAB](https://arxiv.org/abs/2507.10183) diagnostics show current architectures struggling with periodicity and delayed cause-and-effect. Where neural methods outperform, they do so through recency and co-occurrence structure at modest cost. The mission machinery is therefore deterministic by design: predicates, deltas, and burn-downs are exact computations over facts CCS minted, the fence-sitting record among them only if CCS comes to carry it. The learned tier above them, which [our published vocabulary](https://clef-lang.com/docs/internals/pipeline/hyping-hypergraphs/) terms graph heuristic networks, would serve as a prioritizer, suggesting where to look, never what is true. When the evidence justifies that tier, the current architectural trendline favors lightweight models, with state-space designs treating irregular timespans as signal, a natural fit for build events. Predictions from it inherit the framework's standing discipline: the deterministic layer carries guarantees, and a learned ranking never does.
