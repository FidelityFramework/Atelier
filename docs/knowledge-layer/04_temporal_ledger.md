# 04 - The Temporal Ledger

A snapshot of the specific graph answers what the solution is. A sequence of snapshots, differenced, answers where the solution is heading, and that second question has information in it that no single slice holds. The clearest example is the fence-sitting decision. A subgraph that could lower as control flow or as dataflow gets written CPU-flavored because the CPU is the target that exists, and eighteen months of accretion bury the structure that would have gone the other way. Today's graph shows CPU-shaped code and is silent on the distinction between CPU-shaped because it must be and CPU-shaped because that was all there was. The trajectory could hold that distinction only if the compiler recorded it at the decision point, and today nothing does: the control-flow versus dataflow pivot is a witness-side lowering choice in Composer over coeffect metadata, with no score and no recorded decision, and CCS carries no annotation for it. If the distinction is to be a fact at all, it is a CCS saturation annotation, an enumeration of the admissible lowerings and the coeffects that decided among them, never a number, and whether CCS should carry it is an open contract question this sub-folder does not decide. The ledger records the appearance of such an annotation; it never synthesizes one. We call this the counterfactual ledger, and document [05](05_missions.md) builds the capability-arrival advisor on the query it would make trivial, sequenced after that decision.
